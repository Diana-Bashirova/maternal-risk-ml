# Maternal Risk Classifier (MRC) — Model Card

Model Cards предназначены для предоставления важной информации о моделях машинного обучения, включая известные ограничения, подходы к смягчению рисков и показатели безопасности. 

**Опубликовано:** Октябрь 2026 г.

## Информация о модели (Model Information)

### Description (Описание)
Maternal Risk Classifier (MRC) — это прогностическая модель машинного обучения, предназначенная для автоматической триажной сортировки беременных женщин по уровню риска осложнений (низкий, средний, высокий). Модель использует гибридную архитектуру: алгоритм машинного обучения применяется для пациенток в возрасте до 42 лет, тогда как для более старших пациенток действует жесткое бизнес-правило — автоматическое направление к профильному специалисту.

### Model dependencies (Зависимости модели)
Модель построена на базе градиентного бустинга **XGBoost** и интегрирована в пайплайн обработки данных с использованием **Scikit-learn**. Для интерпретации результатов используется библиотека **SHAP**.

### Inputs (Входные данные)
Числовые клинические показатели пациентки:
*   `Age` (Возраст)
*   `SystolicBP` (Систолическое давление)
*   `DiastolicBP` (Диастолическое давление)
*   `BS` (Уровень сахара в крови)
*   `BodyTemp` (Температура тела)
*   `HeartRate` (Частота сердечных сокращений)

### Outputs (Выходные данные)
*   **Класс риска**: `low risk`, `mid risk`, `high risk`.
*   **Вероятность уверенности**: Максимальная вероятность предсказанного класса (от 0.0 до 1.0).
*   **Интерпретация**: SHAP-значения (вклад каждого признака в конкретное решение).

### Architecture (Архитектура)
Модель представляет собой `Scikit-learn Pipeline`, состоящий из двух шагов:
1.  **IterativeImputer (MICE)**: для многомерной импутации пропущенных значений с учетом взаимосвязей между признаками.
2.  **XGBClassifier**: многоклассовый классификатор с методом `tree_method='hist'` и оптимизацией под метрику `mlogloss`.

## Данные модели (Model Data)

### Training Dataset (Обучающий набор данных)
Модель обучалась на **Maternal Health Risk Data Set**. После фильтрации аномальных записей (возраст < 18 лет) итоговый датасет составил **821 пациентку**.

### Training Data Processing (Обработка обучающих данных)
*   **Фильтрация**: Исключение пациенток младше 18 лет.
*   **Разделение**: Стратифицированное разделение на train/test (80/20) для устранения дрейфа данных.
*   **Инжиниринг признаков**: Создание признака `PulsePressure` (разница давлений) и индикаторов пропусков.
*   **Взвешивание классов**: Применены веса классов для компенсации дисбаланса (low=1.0, mid=2.0, high=5.0).
*   **Импутация**: Заполнение пропусков через `IterativeImputer` строго внутри кросс-валидации для предотвращения утечки данных.

## Оценка (Evaluation)

### Approach (Методология)
Оценка модели проводилась по следующей методологии:
*   **Кросс-валидация**: 5-fold Stratified CV для сохранения пропорций классов.
*   **Out-of-Fold (OOF) оценка**: Подбор порога уверенности (confidence threshold) на "честных" предсказаниях, не виденных моделью при обучении.
*   **Композитная метрика**: Оптимизация порога по формуле `Score = 0.3 * Accuracy + 0.5 * Recall@HighRisk + 0.2 * AutoRatio`, где приоритет отдан безопасности (Recall).
*   **Тест на дрейф**: KS-тест (Колмогорова-Смирнова) для проверки идентичности распределений train и test выборок.

### Results (Результаты)
Результаты на отложенной тестовой выборке (для случаев с уверенностью модели ≥ 0.50):

## Предполагаемое использование и ограничения (Intended Usage and Limitations)

### Benefit and Intended Usage (Преимущества и предполагаемое использование)
MRC идеально подходит для медицинских учреждений, которым требуется:
*   Раннее выявление пациенток с высоким риском преэклампсии и гестационного диабета.
*   Автоматизация рутинной классификации для разгрузки врачей.
*   Создание многоуровневой системы безопасности с передачей "серых" зон на ручную проверку.

### Known Limitations (Известные ограничения)
У модели есть ряд ограничений, которые необходимо учитывать:
*   **Возрастные ограничения**: Модель не применяется для пациенток младше 18 и старше 42 лет (для последних работает жесткое правило направления к врачу).
*   **Ограниченный набор признаков**: Модель не учитывает ИМТ (BMI), срок беременности (GestationalAge) и протеинурию, что может снизить точность в сложных клинических случаях.
*   **Синтетические данные**: Часть обучающей выборки была синтетически сгенерирована, что может не полностью отражать реальное клиническое разнообразие.
*   **Калибровка порога**: Порог уверенности 0.50 подобран на небольшой выборке и требует калибровки на реальных продакшен-данных.

## Допустимое использование (Acceptable Usage)

Модель предназначена исключительно для **поддержки принятия клинических решений (Clinical Decision Support)**. Она не должна использоваться как единственный источник истины для постановки окончательного диагноза без участия квалифицированного медицинского персонала. Запрещено использование модели в юрисдикциях, где автоматизированный триаж беременных женщин противоречит местному законодательству.

## Этика и безопасность (Ethics and Content Safety)

### Evaluation Approach (Подход к оценке)
Для обеспечения этической безопасности и минимизации вреда была внедрена асимметричная матрица стоимостей ошибок:
*   **Стоимость пропуска высокого риска (False Negative)**: 50 000 руб. (осложнения, судебные иски).
*   **Стоимость ложной тревоги (False Positive)**: 5 000 руб. (доп. анализы, время врача).
Соотношение 10:1 диктует жесткий приоритет метрики `Recall@HighRisk`.

### Safety Policies (Политики безопасности)
*   **Прозрачность**: Использование SHAP гарантирует, что врач видит, какие именно признаки повлияли на решение модели.
*   **Защита уязвимых групп**: Пациентки старшего возраста (>42 лет), находящиеся в группе повышенного риска, полностью исключены из зоны ответственности ML-модели и автоматически направляются к специалистам.

### Clinical Validation & Expert Review (Клиническая валидация и экспертная проверка)
Вместо традиционного "Red Teaming" для медицинских моделей применяется клиническая валидация:
*   **A/B-тестирование**: Перед полномасштабным внедрением проводится пилотный проект с параллельным принятием решений врачом и моделью.
*   **Ручная проверка "серой зоны"**: Случаи с низкой уверенностью модели (< 0.50) принудительно передаются на ручную проверку врачом, что исключает риск автоматической ошибки в неоднозначных ситуациях.

## Риски и меры по их снижению (Risks and Mitigations)

### Risks (Риски)
*   **Дрейф данных (Data Drift)**: Изменение распределения входных признаков в реальной больнице по сравнению с обучающей выборкой.
*   **Ложное чувство безопасности**: Врачи могут слепо доверять модели, игнорируя клиническую картину.
*   **Пропуск редких патологий**: Модель обучена на общих рисках и может не выявлять специфические редкие осложнения.

### Mitigations (Меры по снижению)
*   **Мониторинг**: Настроен еженедельный KS-тест по ключевым признакам. При p-value < 0.05 система генерирует алерт для переобучения.
*   **Порог уверенности**: Случаи с `max_proba < 0.50` (около 27% выборки) автоматически передаются на ручную проверку врачом.
*   **План дообучения**: Запланировано переобучение модели раз в 3 месяца или при накоплении 500+ новых размеченных случаев из "серой зоны".
*   **Расширение признаков**: В будущих итерациях планируется добавление BMI, GestationalAge и Proteinuria при наличии данных.
